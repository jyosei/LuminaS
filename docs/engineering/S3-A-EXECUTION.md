## A1 接口决策

- 在 EditTag 尾部追加 localIdentity 与 viewEpoch，保留原六字段聚合初始化语义。零值仍可供现有 Recipe-only 调用使用。
- 统一比较同代身份：session、revision、geometry、localIdentity、viewEpoch 必须全部相等。路径和 RenderView 仍另外核对。
- 精确匹配保留全部字段。交互反馈仅允许双方 interactive、同代且路径/视图一致；允许省略 draft/job 相等，保留连续拖杆反馈。不得用允许旧交互帧的规则接受其他局部状态或视图。
- Window 负责递增 viewEpoch；视图或比较/裁剪角色变化时递增，防止视图关闭后又打开的 ABA。局部身份由后续文档快照提供，不由后台重写调用者标签。
- 入队前、后台交付与 Window 提交三处验证。浮点准备帧和取色就绪状态不得由过期任务更新。
- 显式 invalidate 先清当前有效身份和等待项，再发出协作取消。空筛选、切图和关闭不能继续接收旧任务。预解析属于导入会话，普通切图不取消整组预解析。
- 一次请求拥有共享原子取消状态；后台只持 token，不访问 UI 可变对象。取消不释放其他线程仍引用的 SourceFrame 或 QImage。
- 同代交互可继续交付已有帧，保留最新等待项；跨代任务先失效再取消。旧完整源准备仍在退出时不得阻断有效缓存上的 live 通道。
- token 作为尾部可选参数加入源读取、颜色转换与 CPU 渲染入口，旧调用默认空 token。GPT 实现源哈希分块、LibRaw progress callback、ICC 行块与渲染行块轮询；不改变像素数学、RAW 参数、颜色顺序或无局部快路径。
- 无法即时取消的 JPEG 解码、第三方库或既有空间准备采用阶段边界检查；不宣称硬取消或关闭时延已经通过。RAW 进程隔离和故障兜底仍属于 D2，不能以 token 代替它。

## A1 验证要求

1. localIdentity 或 viewEpoch 不同的结果，即使 session/revision/geometry 相同，也不能交付或呈现。
2. 同代交互旧 draft 仍能反馈；新 revision/geometry、路径或视图不能套用该例外。
3. 视图切换 A→B→A 后，第一次 A 的结果被拒绝。
4. invalidate 后旧请求不得更新 lastBase、取色能力、显示缓存或画布；下一个有效请求仍可完成。
5. 快速切图/Undo/Redo、取色取消与窗口关闭覆盖在途任务；旧缓冲引用保持有效直到任务退出。
6. 已取消 token 在读取源或分配整图前返回；在途 CPU 行块协作结束，不返回半张有效图；未取消 token 与空 token 像素一致。
7. 现有连续拖杆、RAW 精算与缓存反馈重叠、显示隔离及导出专项保持通过。
8. 明确记录本次实际命令、退出码、数量、像素差与未覆盖项；不能以旧回归数字代替 A1 验收。

## A2/A3 的后续边界

PhotoDocument / DocumentSnapshot 冻结源身份、完整 Recipe、有序局部层、算法版本和 revision。历史保存小不可变快照，不复制整图像素；预设仍只携带全局 Recipe。

项目以整组照片为单位，SQLite 单 writer 保存到同目录临时目标并原子替换；源文件只读引用，不嵌入照片。未知格式/算法、缺源与 hash 变化、保存失败保旧是强制验收；Undo 历史不持久化。独立恢复副本与完整 UI 在 D 收尾。
