# 原UI设计与当前Qt窗口差距

2026-10-12，按用户“检查原设计是否有UI部分”阅读本地方案及生产代码。结论：**原设计有完整UI部分，当前Qt窗口尚未落地主要视觉规范和工作区结构。** 本文件是核对与下一版执行依据，不是UI改版完成记录。

用户随后授权“开干”，首轮UI已经接入：默认深色/手动浅色切换、选片/编辑切换、可折叠白平衡/光线/色彩/构图、单项复位、真实预览直方图、简化画面信息/详细tooltip、短撤销按钮与详细tooltip、可滚动调整侧栏。下文差距表是改版前快照；当前实现与实测见ADJUSTMENTS-V1-RESULTS.md。局部/修饰未完成前不展示假入口；自动跟随系统、更多图标/快捷操作及完整DPI验收尚未完成。

3. [交接需求](../../handoff/sol-implementation-v1/01-REQUIREMENTS.md)优先于旧docs/01-product.md及旧原型。旧“摄影/图层合成”“调色/人像/局部”、AI和假导出按钮不得照搬。

## 当前实际差距

| 方面 | 原稿与有效修订 | 当前Qt窗口 | 下一版具体处理 |
|---|---|---|---|
| 视觉层次 | 框架/面板/画布三级中性灰、紫色少量强调 | 系统默认亮控件、深色画布，焦点与主要动作层次弱 | 统一原生Qt配色与间距，明暗主题；画布中性衬底独立于主题 |
| 工作区 | 选片/编辑 | 选片和调整长期混在同一窗口 | 选片扩大画布、隐藏调整面板；编辑展开分组侧栏；视图切换不改recipe/选片 |
| 操作栏 | 全局操作与上下文分开、减少多行占用 | 长文本按钮挤在一个工具栏，撤销带完整文件名 | 文件入口/选片导航/历史分组；撤销细节放tooltip；上下文只在具体工具启用时出现 |
| 参数面板 | 紧凑分组、可折叠、数值一致、单项复位 | 一个QFormLayout平铺六项及四个大按钮 | 分为基本/曲线/颜色/细节/几何，随真实算法逐组提供；约320 DIP可调宽、垂直滚动 |
| 工具状态 | 图标有提示与选中态、当前目标明确 | 裁剪是按钮，默认浏览光标是箭头 | 浏览为张开手，拖动握手；滚轮指针中心缩放。裁剪显式十字状态，完成/Esc恢复浏览 |
| 信息显示 | 当前图、处理/预览质量、状态分层 | 文件/原尺寸/预览/颜色合同挤成一段，胶片条标签冗长 | 画布边保留短文件名与4K标识；技术说明折叠到详细信息；状态栏显示缓存进度/失败 |
| 胶片条 | 真实照片、当前图/多选/标记区分，可折叠 | 真实列表已实现；靠文本箭头表示当前图 | 清楚的当前边框、独立多选/选片符号、就绪状态，快捷隐藏；保留真实素材比例 |
| 比较与缩放 | 易达比较、视口比例与质量明确 | 原图比较在侧栏，双击适屏/滚轮操作缺少直观默认小手 | 全局比较入口、适屏和预览缩放；4K比例不可标为原片完整100% |
| 曲线/直方图/HSL | 原型已有布局示意 | 尚未实现 | 随真实调色功能添加真实统计/曲线控件；不复制原型假曲线 |

## 本轮实际修改

先完成明确请求的画布浏览交互，不在仅核对设计时宣称已完成整套UI改版：有图默认张开手，左键按下握手拖动，松开恢复张开手；无需进入某个编辑工具或按修饰键。滚轮以指针为中心缩放，增加只有pixelDelta的触控板事件支持。裁剪才用十字，退出恢复小手；重复缓存结果更新不清掉正在拖动的状态；右键松开不终止左键拖动。双击适屏仅在浏览时有效，避免裁剪中误操作。

修改src/app/canvas.h/.cpp和现有tests/s0_tests.cpp交互验证；数学/图片源引擎未改。构建和测试证据见evidence/navigation-*，最终结果追加STATUS.md。新参数尚未实现，完整UI改版尚未执行；能力清单与补齐顺序见[ADJUSTMENT-COVERAGE.md](ADJUSTMENT-COVERAGE.md)。

正式UI实施须实际检查1366×768、1920×1080、150/200%缩放、中文输入/焦点、侧栏与胶片条收起恢复，确认所有已显示功能可用。控件位置变化要复测4K持续反馈、RAW精算时拖动和缓存切图；不能把浏览器截图当Qt高DPI验收。

## 2026-10-13 原生工作区改版

本批本机检查已收尾，最新精确结果见 [UI-V2-RESULTS.md](UI-V2-RESULTS.md)：构建与RAW/JPEG启动退出0，默认CTest3/3，原生组合7通过；真实JPEG在两种屏幕预算和DPR1/1.5/2下布局通过。下面保留实现与初始检查说明，不取代最新结果报告。系统真实IME、多显示器/设备/目标机与正式用户可用性仍待验证。

已用原生Qt实现四层交互：顶栏为品牌、选片/编辑、导入菜单、撤销/重做/主题；画布上下文为小手/裁剪/适屏/原图比较；右侧为直方图与可折叠光色/曲线/HSL/构图卡片；底部为导航/标记/筛选/胶片条开关。图标为自绘矢量笔画，按Qt逻辑尺寸渲染，没有照搬商业品牌素材。主题、卡片和胶片条delegate独立放在src/app/ui_primitives.*，不扩大生产图像核心依赖。

参考与产品取舍：Lightroom [Develop模块](https://helpx.adobe.com/lightroom-classic/desktop/process-and-develop-photos/develop-module-tools.html)提供照片、直方图、编辑面板/胶片条的分工；Photoshop [上下文任务栏](https://helpx.adobe.com/photoshop/desktop/get-started/learn-the-basics/boost-workflows-with-the-contextual-task-bar.html)把相关动作放到当前操作附近；[像素蛋糕调色工作流](https://wiki.pixcakeai.com/guide/14643.html)支持先整体光色、再曲线分色和局部的组织。上述是官方帮助研究，没有安装实测商业软件；四层方案和具体尺寸为Lumina自己的设计判断。

胶片条当前图以紫色边框突出，多选使用底色，保留/排除使用独立符号，缓存就绪/失败使用状态点；仍保留文字item内容供辅助信息与测试。单项复位使用图标与可访问名称。技术RAW/JPEG增益语义放到白平衡提示，标签不再占用滑杆大部分宽度。小窗口胶片条缩为紧凑尺寸，高度不足500 DIP时自动收起并解释原因，扩大窗口按用户开关恢复；侧栏继续可滚动。

本批初始build退出0；Windows原生既有手势/文字焦点/曲线HSL/析构回归6通过0失败，2399ms，见evidence/ui-v2-build.log、ui-v2-native.txt。已检查真实Qt抓图的分层与平滑曲线。新布局/DPI回归及真实照片外观仍在执行；新增布局测试初次因缺少hash helper编译失败已补函数，最终以新日志为准。不能把初始截图或未完成DPI检查记成全套UI验收通过。
