# 开发路线与性能验证

## 先验证，再堆功能

**P0：决定主方案能否落地。** 输入一张 24 MP 图片，完成中文桌面窗口、GPU/CPU 曝光与合成、ICC 显示、三层蒙版、RAW 样本读取、限额缓存与一个 AI 点选验证。输出基准报告和依赖清单，然后搭正式 workspace。

五个必须通过的门槛：

1. UI：中文字体与 IME、输入焦点、200% DPI、双屏缩放、触控板、笔压/笔刷事件、键盘可达性；拖动参数后按需重绘，空闲功耗合理。
2. 图像：RAW 白平衡与相机矩阵正确；肤色、高光与宽色域照片通过人工/像素检查；显示和导出各用正确 ICC，不发生双重伽马。
3. 引擎：tile 缓存预算有效；移动视口不出现黑块/接缝；CPU/GPU 结果在定义容差内；大图和显存不足有受控退化。
4. 部署：一台干净 Windows 11 x64 上解压可运行；缺开发运行时也能启动；原生库构建特性/许可清单可复现。
5. AI：完整 MobileSAM 编码器 + 解码器导出并验证；先在 CPU 跑通，GPU 只是加速；未安装 AI 包时软件仍能完成基本修图。

egui 未通过 UX 门槛则更换 UI，不推翻核心。GPU 未达到性能门槛则先定位传输、调度与全图重算，不能凭一次跑分盲目更换语言。

## 交付里程碑

| 阶段 | 可交付结果 | 退出条件 |
|---|---|---|
| P0 | 一份技术可行性报告 + 小型实验程序 | 上述门槛通过，或写出明确替代路线 |
| v0.1 | 能完成 RAW / RGB 打开、调色、多层、手动蒙版、传统降噪、保存恢复与导出 | 测试清单中的 RAW 照片闭环；大图预算、颜色与保存故障检查通过 |
| v0.2 | 去瑕疵、仿制、修补、减淡加深与更完整局部调色 | 非破坏修饰、撤销、跨 tile 边界、采样对齐与肤色观感通过 |
| v0.3 | 液化、AI 点选、可选 AI 降噪、一个本地生成适配器 | 坐标一致、模型卸载、任务取消、选区外不变、接受为图层通过 |
| 跨平台/稳定版 | macOS/Linux、项目迁移、扩展协议 | 相同参考图像与项目跨平台结果一致，平台输入/ICC 适配通过 |

不在不了解投入人数、经验与可用工时的情况下给确定工期。个人开发全职也应按多个阶段推进；P0 的实际耗时和质量会决定后续估算。文本、矢量、CMYK、印前、PSD 高保真兼容、巨幅全景和自动脸型修饰不进入首版承诺。

## 性能预算：待测目标，不是当前结果

基准场景 A：Windows 11、8 GB RAM、SSD、4 核 CPU、可用 DX12 集显、1080p 屏幕、24 MP 照片、一个源层 + 五个调整层 + 一个小范围修饰层；模型未加载。记录实际 CPU/GPU/驱动，不能只写“普通电脑”。场景 B 使用 16 GB + 独显，单独测试 AI 和更多满幅像素层。

| 指标 | 场景 A 初始目标 | 计量方式 |
|---|---|---|
| 核心安装包 | 压缩包 ≤ 120 MiB，包含字体与必需 DLL，不含可选 AI | release 构建统计；解压后的大小另列 |
| 冷启动至可操作窗口 | p95 ≤ 2 s | 至少 20 次；分开记录首次安装、首次 shader 编译与后续启动 |
| 空项目 RAM | private committed bytes ≤ 200 MiB | 启动稳定后测，working set 另列 |
| 空闲 CPU | 30 s 窗口平均 ≤ 1% 总机 CPU | 无交互/任务，注明逻辑核数和测量工具 |
| 编辑稳态 RAM | 主进程 + worker ≤ 1.2 GiB | 显影完成后，同一场景循环操作；RAW 解码峰值单列 |
| RAW 打开峰值 RAM | ≤ 2 GiB，超过时限制并发/格式并报告 | 包含解码工作进程；60 MP 另设压力场景 |
| GPU 驻留预算 | 可配置 256–512 MiB 起步 | 纳入纹理池、临时结果、UI 与 halo；共享 GPU 内存不与 RAM 简单相加 |
| 拖动曝光到可见预览 | p95 ≤ 50 ms，争取 30 FPS 以上 | 1080p 视口/mip；不是每次全分辨率显影 |
| 交互停止后高质量视口 | p95 ≤ 500 ms | 基础调整场景；降噪/修复分别记录，不混入该指标 |
| 蒙版笔刷到反馈 | p95 ≤ 33 ms | 记录笔刷事件到屏幕显示；检查边界 tile 与快速笔划 |
| RAW 首张预览 | p95 ≤ 1 s，前提存在嵌入预览 | 没有嵌入预览单列；完整显影根据机型和算法报告 |

首次 shader 编译、RAW 解码、传统降噪与全尺寸导出不能用这些交互指标概括。性能报告同时公布预览分辨率、质量档、颜色精度和相机格式，避免用降质掩盖问题。

GPU 与 AI 各有自己的预算，但共享物理资源；开始重型生成时降低预览占用并显示可用能力。低显存卡不承诺本地扩散生成。AI 时间包括模型冷加载、编码、交互解码、后处理四段，不只报一个“推理时间”。

## 需要的正确性验证

- 数学/颜色：曝光、alpha、混合顺序、ICC 与高光；CPU 作为参考，比较 GPU 数值和实际图像。参考输出固定算法版本。
- 视觉：肤色、细节、噪点、棋盘/斜线、边缘透明度、跨 tile 降噪和修补、液化冻结与重建。使用有许可的相机样本，不公开用户私人照片。
- 保存/历史：原图哈希不变；撤销重做再导出一致；重启恢复一致；保存时强制终止进程、磁盘满、缺外部原图、旧格式与未知节点。
- 异步：快速滑杆变化/撤销不会被旧任务覆盖；导出期间修改画面仍输出启动导出时的 revision；关闭 AI / 解码进程后可恢复。
- AI：裁片缩放与坐标、mask 方向、边缘范围、颜色契约；选区外像素不变；拒绝/取消不改文档；模型缺失/损坏有明确反馈。

## 建议的第一批任务

按依赖顺序做，不把所有功能同时开工：

1. 固定文档坐标/颜色/命令契约，建立 24 MP 与小型测试资产。
2. 中文 UI + JPEG 打开 + wgpu 曝光 + CPU 对照 + 视口缩放。
3. 三层合成、蒙版、revision、滑杆事务与撤销。
4. 有预算的 tile/mip 缓存、测量工具与空闲重绘。
5. ICC 显示与 JPEG/TIFF 导出。
6. Bayer RAW 显影验证与原生 worker 部署。
7. SQLite 项目快照、崩溃恢复和 8 GB 机器压力检查。
8. 完整 MobileSAM ONNX 实验与可选 AI 包结构。

P0 与 v0.1 的文档、数据类型和验证程序都进入开源仓库；模型和巨型照片作为可下载资产，保持仓库可快速克隆。
