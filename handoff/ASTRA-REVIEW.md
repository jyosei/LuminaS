# Lumina · Astra 方案审查入口

版本：Review v1，2026-10-12。状态：等待方案审查；没有生产编辑器、性能跑分或已发布软件。

本交接包用于审查并敲定产品范围、技术路线与程序架构。包中的“包体预算”是未来软件的目标，与本 ZIP 的文件大小无关。

## 用户已经明确的需求

1. 开发一个容易使用、轻量化的图像处理软件，并计划开源。
2. 长期能力对标 PS 常用功能：RAW 解码、多图层编辑与实时预览、调光调色、算法降噪、液化、修补、仿制图章、AI 视觉选区，随后考虑局部选区 AI 改图。
3. 平台优先 Windows，随后 macOS / Linux；首要场景是人像与摄影修图。
4. 动机是像素蛋糕的付费模式与 PS 的高资源消耗；易用性和轻量化是核心约束。
5. 第一版界面被认为过于简单、审美不足；后续界面需参考 PS 和像素蛋糕，拥有成熟摄影编辑器的工具组织与视觉层次。

## 当前方案与其状态

| 项目 | 当前建议 | 状态 |
|---|---|---|
| 产品定位 | 摄影/人像工作流优先，PS 常用能力逐步覆盖 | 与用户方向一致；具体版本范围待定 |
| 系统基线 | Windows 11 x64；8 GB 基础验收档 | 工程假设；用户只确认 Windows 优先 |
| 核心 | Rust，图像核心与 UI 分离 | 工程建议，未实现 |
| UI/GPU | egui/eframe + wgpu；Qt 为替代路线 | 尚未证明可承载第二版 UI 的全部交互 |
| RAW/色彩 | LibRaw 读取、独立显影管线、Little CMS | 显影质量与自研范围尚未验证 |
| 文档/缓存 | 非破坏图层、分块/mip、限额缓存、命令与 revision | 架构建议，未实现 |
| 项目格式 | SQLite + 内嵌原图 + 分块数据/恢复 | 需要与更简单方案比较 |
| AI | 按需独立 worker；MobileSAM 候选；本地生成服务接口 | 完整 ONNX、部署与模型选择未验证 |
| 开源许可 | Apache-2.0 候选 | 用户未敲定；未创建 LICENSE |
| 基础使用 | 离线、无账号/订阅；AI 可选安装 | 对用户动机的产品建议，需审查商业/分发边界 |
| 性能 | 安装、启动、驻留、延迟分别限额 | 仅预算目标，没有实测结果 |

用户未提供：开发人数、语言经验、可投入工时、目标机型、主要相机/RAW 样本、最低 Windows 版本、是否需要 PSD 互通。不要在缺这些信息时给精确工期或相机兼容保证。

## 已完成与未完成

已完成：产品/技术/架构/路线文档；第二版浏览器 UI 原型；AI 生成样片；对部分交互、主题和布局的浏览器检查。

原型可运行的是近似颜色预览、参数输入、工具/页签切换、撤销重做与模拟候选流程。原型没有真实 RAW 解码、GPU 图像引擎、完整图层计算、真实修补/液化、AI 分割/生成或正式项目保存。菜单文本、曲线布局、部分人像参数属于设计示意；虚拟副本不是完整独立编辑文档。原型的视觉效果和浏览器时延不能作为桌面性能证据。

静态截图便于直接查看；`prototype/lumina-studio-preview.html` 可在现代浏览器中打开。照片内嵌，图标/提示定位库从 CDN 加载；断网时可能缺少图标。它的依赖和包体不代表未来桌面应用。完整生产 UI 不因 HTML 原型成立就自动证明 egui 可行。

## 请 Astra 输出什么

不要仅润色或认同当前建议。请给出：

- 对核心目标和首版范围的判断，以及需要删除/推迟的功能。
- 逐项技术选择：采纳、调整或拒绝，说明证据与工程取舍。
- 最多五个最高优先级风险，给出验证办法、通过条件与失败后的替代路线。
- 敲定的技术栈和架构边界；实测前无法确定的事项保持显式待验证。
- 更精简的 P0 顺序与第一批工程任务；工期按人员/经验假设给区间。
- 第二版 UI 能否兼顾易用、专业密度与目标框架，必要时指出具体控件/布局问题。

对技术事实采用官方资料并记录版本/日期；对性能、工期和算法质量区分证据、估算与待测目标。请重点检视下列决策表中暴露的弱点，不把已有代码草图当成不可变的设计。
