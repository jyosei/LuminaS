## 本轮整理时识别的设计弱点

- “高质量显影自己实现”是整个方案最容易低估的部分；解码库选对不等于得到可靠的摄影颜色和细节。
- egui 是基于工程简洁的建议；用户明确提高 UI 要求后，应该重新评估实现第二版界面的交互成本。换 Qt UI 也涉及额外 ABI、事件和维护工作，不是零成本替换。
- P0 的范围、v0.1 的范围和架构拆分可能同时过重；需要审查者主动削减，而不是按文档逐项开工。
- `.lumina` 存储、完整 CPU 回退、GPU 显示 LUT 与跨 tile 运算都需要样本和故障测试；目前只有设计。
- 界面中的人像/液化控制代表长期产品方向，不意味着这些功能属于首个可发布版本。

## 建议的审查结论格式

每项决策填写：**结论 / 理由 / 证据 / 最小实验 / 通过条件 / 失败替代 / 是否阻塞首版**。

若团队信息缺失，请列出影响选型的假设，给出默认推荐与切换条件；不要将所有问题都退回给用户。需保持“易用、轻量、摄影优先、Windows 优先、计划开源”的主目标。
