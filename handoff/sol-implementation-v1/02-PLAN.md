**第一轮的明确边界**

只执行S0，完成真正可编译和运行的最小桌面窗口。不要一轮实现S0–S7，不在本轮做AI/RAW算法研发/GPU计算/SQLite完整系统，也不要创建只有空类的全量架构。可以设计后续所需的极小接口，不能借接口设计扩成平台项目。

**每轮发给Sol的任务格式**

“按交接包执行阶段 Sx。先读 `06-PROGRESS.md` 和实际代码，确认上一阶段证据；实现本阶段产物，运行相应检查，更新工程状态。普通可逆实现自主完成；遇到真实缺失输入继续独立工作并记录待验证项，不伪造通过。报告修改、运行命令、证据、限制和下一阶段依赖。”

**建议源码组织：按阶段生长**

```text
Lumina/
  CMakeLists.txt
  CMakePresets.json
  src/
    app/          # 窗口、选片、胶片条、画布、属性控件
    core/         # 资产、文档、参数、命令、坐标
    io/           # RGB编解码、元数据、尺寸预检
    raw/          # LibRaw调用与源显影合同
    color/        # ICC与工作/显示/输出转换
    render/       # CPU算子、代理、tile与显示帧
    edit/         # 蒙版与仿制
    jobs/         # 取消、版本、限额与线程任务
    storage/      # 项目、本组记录、恢复
    batch/        # 参数复制、串行成组导出
  apps/raw-worker/
  tools/raw-probe/
  tests/          # 数学、几何、异步、持久化等有意义的验证
  docs/engineering/
```

这不是必须一次创建的目录清单。核心少量构建target即可。避免将复杂调度、插件接口或统一跨语言ABI当成S0准备工作。

**时间预算**

2026-10-12后续执行补充：用户确认当前R7样片验证优先，真实近45MP覆盖不作为S1/S2推进阻碍；输入设计上限仍45MP，实机未测项明确保留。S1 R7工程实验现有6组真实证据，正式RAW质量/后期可调性继续在S2及P0验证；不要把缺45MP单独写成当前阶段必须停止的条件。

先沿用审查的宽预算：P0约4–8个工程周；v0.1完整周期原粗估8–15个月。不是Sol运行时长或交付承诺，不把模型输出速度当开发工期。小批量与低清预览减少部分范围，但45MP显影/导出、色彩、输入与恢复仍要实测；S1/S5后重估，暂不给各行硬截止日期。

**允许的失败处理**

- Qt/编译工具未安装：先记录可用组件和准确缺口，完成可独立源码与构建说明；如要安装，遵守实际环境权限，不谎报可运行。
- RAW样本缺失：先完成probe与JPEG主线，RAW质量标待验证；不能从首版删除CR3。
- 无8GB实机：开发机结果标实际配置，实机门槛待验证；不能伪称模拟限额就是低配性能证明。
- CPU代理慢：先测热点、降低预览/限制并行，再决定局部GPU加速；不能改45MP完整导出要求。
- 完整RAW质量不合格：提交证据与复用替代，不偷偷变成只支持JPEG的v0.1。
